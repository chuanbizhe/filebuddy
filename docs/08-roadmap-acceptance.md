# 开发路线与验收标准

## 1. 建议分期

| 阶段 | 交付 | 不做什么 |
| --- | --- | --- |
| P0 基线 | Workspace、身份、只读 MCP/API、本地路径隔离、Windows 客户端 | 不做多设备同步、计费扣款 |
| P1 闭环 | 读写/Patch、版本冲突、原子写入、P2P 与 Relay、复制给 AI | 不做 Shell/Git/全盘权限 |
| P2 大文件与商业化 | OSS 临时传输、用量、余额、价值报告、macOS/Android | 不做永久云盘 |
| P3 扩展 | Agent Profiles、Explorer 入口、更多本地能力 | 先评估安全模型再开放能力 |

## 2. P0/P1 验收场景

1. 用户可在 Windows 通过系统选择器创建一个只读 Workspace；Agent 只能看到 `/workspace`。
2. Agent 可列出目录、读取文件和范围读取，不能访问根目录、真实路径或相邻目录。
3. 用户切换为读写后，生成的 MCP/API/Prompt 一致更新；写入工具才可用。
4. Agent 对文本文件使用 Patch 成功后，本地立即出现修改，响应携带递增版本。
5. 用户在 Agent 写入前本地修改同一文件，系统返回 `VERSION_CONFLICT`，原文件不被覆盖。
6. P2P 成功时数据不经 Relay；P2P 失败时小操作自动改走 Relay，用户看到可理解状态。
7. 超过服务端阈值的大文件经临时 OSS 直传，校验完成后对象被删除；异常对象会过期清理。
8. 设备离线时 Agent 收到 `DEVICE_OFFLINE`，用户界面说明需要打开哪台设备。

## 3. 上线前安全清单

- 路径穿越、符号链接与权限绕过测试；
- 会话令牌过期、撤销和跨用户访问测试；
- 并发写入、断电/崩溃中的原子写入恢复测试；
- Relay 不落盘与 OSS 签名时效测试；
- 用量记账、失败重试与重复回调幂等性测试；
- Android 目录授权、后台回收与网络切换测试。

## 4. 产品决策守则

每项需求先回答：它是否让“把本地文件夹直接交给 AI”更简单、更安全或更稳定？如果要求普通用户理解 Endpoint、Token、WebRTC、TURN、NAT、OSS 或 JSON Schema，就应把这些细节隐藏在产品内部。
