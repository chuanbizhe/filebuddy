# 多端客户端设计

## 1. 共同职责

三个客户端都承担：登录、设备注册、Workspace 管理、系统目录授权、后台连接、请求执行、版本检查、原子写入、传输管理、连接统计、活动记录及会话撤销同步。

客户端是本地文件权限的唯一执行者。服务端和云端 Agent 不能直接触达用户文件系统。

## 2. Windows（P0）

Windows 首版提供完整主体验：项目管理、文件夹选择、托盘常驻、开机启动、后台连接、连接日志和流量统计。未来可增加资源管理器右键入口“使用文小哥连接 AI”，但不作为 v1.0 阻塞项。

## 3. macOS（P0）

保持与 Windows 相同的核心流程和文案，使用原生文件夹授权及系统安全机制。应用需清楚表达当前已获授权的目录，避免误导用户认为可访问整个磁盘。

## 4. Android（P0）

必须使用系统文件选择器授权目录，并持久化该 URI 权限。需要设计后台连接策略以应对休眠、电池优化、Wi‑Fi/蜂窝网络切换、NAT 变化、进程回收和自动重连。

设备离线必须返回 `DEVICE_OFFLINE`，不能伪装为文件不存在。对耗电、后台持续连接和移动流量的影响应在设置中透明说明。

## 5. 本地执行要求

- 请求先经本地权限与路径校验，再实际执行；
- 写入使用同目录临时文件与原子替换；
- 目录扫描、文本搜索和范围读取须支持取消与大小限制；
- 客户端可安全恢复未完成的 Transfer，并在恢复后清理过期任务；
- 操作记录不存储不必要的文件内容，仅保留审计所需元数据。
