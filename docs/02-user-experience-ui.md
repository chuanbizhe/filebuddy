# 体验与 UI 规范

## 1. 体验原则

界面要像可靠的本地工具，而非“炫技 AI 产品”。避免渐变、发光、星空背景、夸张机器人插画、满屏提示词和复杂仪表盘。

- 白色或极浅暖灰背景；
- 以白底圆角卡片组织信息，细边框和轻阴影即可；
- 深灰文字、克制的蓝色作为操作强调色，绿色只用于在线/成功状态；
- 信息先讲“项目、连接、权限”，技术细节仅在二级页面出现；
- 单页只保留一个主要操作，按钮文案用自然语言。

## 2. 基础视觉令牌

| 项目 | 建议 |
| --- | --- |
| 页面背景 | `#F7F7F5` 或近白 |
| 卡片 | `#FFFFFF`，1px `#EAEAEA` 边框 |
| 圆角 | 卡片 16px；输入与按钮 10px |
| 正文 | `#242424`；辅助文字 `#6B6B6B` |
| 主色 | 低饱和蓝 `#2563EB` |
| 字体 | 系统字体；中文优先苹方/微软雅黑等系统回退 |
| 间距 | 8px 基线，卡片内边距 20–24px |

不将技术状态做成夸张视觉。连接状态使用小圆点加文字，如“在线”“通过中转连接”。

## 3. 信息架构

```text
项目
├── 项目列表
├── 项目详情
│   ├── 复制给 AI
│   ├── 连接与设备
│   ├── 权限
│   ├── 活动记录
│   └── 价值报告
└── 添加项目

账户
├── 套餐与中转余额
├── 设备
└── 设置
```

## 4. 关键页面

### 4.1 项目列表

顶部为“项目”标题和“添加项目”按钮。每个项目一张卡片：名称、在线状态、授权目录的可读显示名、权限标签、最后活动时间。空状态用一句解释与“添加第一个项目”按钮，不使用 AI 风格插画。

### 4.2 项目详情

首屏按优先级放置：项目名、在线状态、授权目录、权限、主按钮“复制给 AI”。连接方式、余额和本月价值报告放在下方小卡片；路径可复制但不在分享内容中暴露给 Agent。

```text
← 项目

EloOffice                                      ● 在线
D:\\Projects\\EloOffice · 读写

[                    复制给 AI                    ]

连接状态                         权限
直连                             读写，删除已关闭

本月已节省 ¥18.42
直连率 96.3% · 36.8 GB 未经过中转服务器
```

### 4.3 创建项目

采用单列表单卡片：项目名称、文件夹、访问权限、允许删除。文件夹必须由原生系统选择器选取；“允许删除”解释其影响并默认关闭。提交按钮为“创建项目”。

### 4.4 复制给 AI 弹层

默认展示一段可复制的自然语言接入内容；支持在“通用 Agent、ChatGPT、Claude、Codex、自定义”之间切换。MCP 地址/API 地址置于“高级连接信息”折叠区。复制成功仅使用短暂提示，不弹出冗长说明。

### 4.5 价值报告

用清晰的金额和流量说明价值，避免营销化大数字。展示实际支付、P2P 流量、中转流量、临时空间峰值、等效全中转成本与节省金额；每项费用均可查看计算方式。

## 5. 状态与文案

| 状态 | 用户文案 | 建议动作 |
| --- | --- | --- |
| 在线直连 | 已连接 | 无需额外操作 |
| 在线中转 | 通过中转连接 | 可查看中转使用量 |
| 连接中 | 正在连接 | 显示简短进度 |
| 离线 | 承载此项目的设备不在线 | 提示打开对应设备上的文小哥 |
| 冲突 | 文件已在本地更新 | 提示 Agent 重新读取后再修改 |

不要将 `DEVICE_OFFLINE`、`VERSION_CONFLICT` 等协议错误直接暴露给普通用户。
