# 服务端、计费与价值报告

## 1. 服务端职责

FileBuddy 服务端是控制面而不是文件云盘。它负责账户、设备注册、Workspace 元数据、认证、会话、信令、连接路由、Relay、Transfer 凭证、用量计量、账单和审计。

OSS 文件内容应由客户端/Agent 直传；Relay 仅在必要时流式中转且不长期落盘。

## 2. 核心数据对象

| 对象 | 关键字段 |
| --- | --- |
| User | 身份、套餐、余额、状态 |
| Device | 所属用户、平台、公钥、在线状态、最后心跳 |
| Workspace | 所属用户、名称、设备、权限、稳定公开标识 |
| Session | Workspace、Agent、权限快照、过期时间、撤销状态、连接方式 |
| Transfer | 状态、大小、哈希、过期时间、OSS 对象、计费归属 |
| UsageRecord | P2P/Relay/OSS 字节、临时空间时长、来源与时间 |
| AuditEvent | 调用者、操作、路径摘要、结果、版本、时间 |

## 3. 计费模型

基础套餐为 ¥1.99 / 月，售卖的是连接服务：设备连接、P2P 协商、无限 P2P 流量、基础文件能力及 MCP/API 接入。

无法直连产生的 Relay 流量、OSS 上传下载与临时空间占用，统一从“中转余额”按公开规则扣除。UI 可以按“中转流量”和“临时空间峰值”分别展示，但不要把临时缓冲误导为永久存储配额。

扣费应以服务端用量记录为唯一依据，包含幂等键、防重复扣费、失败补偿和可追溯账单明细。价格、阈值和折算规则应支持后台配置与版本化。

## 4. Value Report（价值报告）

价值报告是 P0 的信任与商业化功能，不是装饰性统计。项目详情显示本月已节省金额、直连率和未经过文件中转服务器的流量；完整报告展示：

- P2P、Relay、OSS 三类传输量；
- 临时空间峰值与实际占用时长；
- 本月实际支付与余额消耗；
- 按公开计费规则计算的等效全中转成本；
- 节省金额与计算方式。

所有“节省”必须由真实传输数据与可点击查看的公开公式计算，不能使用无法证实的营销原价。

## 5. 稳定地址与未来扩展

Workspace 的公开连接地址保持稳定，例如 `https://mcp.filebuddy.example/p/{workspace}`。它指向控制面，由控制面解析当前设备和可用通道。v1.0 仍限制一个 Workspace 一个主设备；未来可在不改变公开地址的前提下扩展多设备副本与同步策略。
