# 文小哥 FileBuddy 产品设计文档 v1.0

## 1. 产品定义

**中文名：文小哥；英文名：FileBuddy。**

> 文小哥 FileBuddy，让云端 AI 安全地直接使用用户授权的本地文件夹。

技术定义为 **Local Workspace Gateway for AI Agents**。它为云端 AI / Agent 提供受限的本地文件能力，而不是把用户电脑暴露为一台远程机器。

用户的主流程应当只有四步：

```text
选择文件夹 → 创建项目 → 复制给 AI → AI 读写本地文件
```

用户无需理解 MCP、端口映射、NAT、WebRTC、OSS 或 API Token。

## 2. 问题与目标

云端 AI 通常无法直接访问本地项目，用户只能在“上传—处理—下载—覆盖”之间往返。代码项目、Office 文档和资料库每次变化都要重复这个过程，既慢也容易出错。

v1.0 的目标：

- 让用户把一个明确授权的本地目录交给云端 Agent；
- 优先通过 P2P 直连，失败时自动降级；
- 用版本检查与原子写入避免覆盖用户的最新修改；
- 将连接、权限、计费和价值感知做成完整闭环。

非目标：云盘、跨设备同步、远程桌面、全盘访问、模型/聊天产品、RAG 知识库，以及 Shell、Git、Office 专用操作能力。这些均可作为后续扩展，但不能影响 v1.0 的安全边界。

## 3. 用户与核心场景

| 用户 | 场景 | 成功结果 |
| --- | --- | --- |
| 开发者 | 云端 Coding Agent 修改本地项目 | Patch 直接落到项目，未覆盖本地新改动 |
| 知识工作者 | AI 整理本地资料或文档 | AI 可在授权目录内读取、生成与更新文件 |
| 自动化用户 | 云端工作流处理本地文件 | 无需开放公网 IP 或手动搬运文件 |

## 4. Workspace 模型

**项目（Workspace）** 是一个用户主动授权给 AI 使用的本地目录。v1.0 中，一个 Workspace 只绑定一个主设备和一个本地目录；不处理多副本同步及冲突合并。

云端只看到统一虚拟根目录 `/workspace`，永远不暴露真实路径。例如 `D:\\Projects\\EloOffice\\src\\main.ts` 对 Agent 显示为 `/workspace/src/main.ts`。

创建项目需要：名称、本地目录、只读或读写权限、以及独立的“允许删除”开关。创建后直接进入项目详情页。

## 5. 用户主流程

```text
安装并登录
  → 添加项目
  → 通过系统选择器授权一个目录
  → 设置读写与删除权限
  → 创建 Workspace
  → 点击「复制给 AI」
  → 将内容粘贴到所用 Agent
  → Agent 建立连接并调用文件工具
  → 本地文件即时生效、客户端展示活动记录
```

首次可用的验收标准是：用户在 Windows、macOS 或 Android 选一个目录，创建可读写 Workspace，把生成内容交给支持的 Agent，Agent 能读取并安全修改其中一个文本文件。

## 6. 关键产品能力

### 6.1 复制给 AI

这是产品的主行动。每个 Workspace 自动生成 MCP 连接、REST API 连接以及与当前权限一致的 Agent 提示词。普通用户只见“复制给 AI”；高级入口才显示 MCP 与 API 详情。

提示词必须包含 Workspace 名称、当前权限、连接方式和工作规则：优先直接调用工具、不访问 `/workspace` 外路径、写入前读取最新版本、优先 Patch，以及遇到离线或版本冲突时的处理方式。

### 6.2 文件能力

v1.0 支持：目录浏览、文件信息、完整/范围读取、创建、写入、Patch、重命名、移动、复制、删除、文件名搜索、文本搜索和大文件上传/下载。

默认优先传递操作与差异，而不是反复传完整文件。删除权限默认关闭。

### 6.3 连接体验

对用户只展示“已连接”“正在连接”“通过中转连接”“设备离线”等可理解状态。P2P、Relay、OSS 的选择由系统完成，不能让用户在主流程中做网络决策。

## 7. 首版平台范围

Windows、macOS、Android 均为 P0。Linux、iOS、NAS、Docker 和 Server 端 Agent 属于后续版本。

## 8. 商业模式概览

基础连接服务为 **¥1.99 / 月**，包含设备连接、P2P 协商、无限 P2P 流量、基础文件读写与 MCP/API 接入。无法直连时的 Relay 流量和 OSS 临时空间按量从“中转余额”扣除；中转空间不是永久云盘。

产品需要以价值报告说明：实际费用、直连率、未经过中转服务器的流量、等效全中转成本与用户节省金额。计算口径必须可查看，不能制造虚假原价。
