# Workspace 与安全模型

## 1. 安全边界

FileBuddy 的基本原则是：**用户选择一个目录，才等于授权 AI 访问这一个目录。** 安装客户端绝不等于 AI 可以访问整台设备。

系统涉及六个明确对象：User、Device、Workspace、Agent Connection、Session、Permission。每次请求都必须绑定到它们，且只可访问会话已授予的单个 Workspace。

## 2. 路径隔离

- 真实磁盘路径只保留在本地客户端；
- 对外协议统一使用 `/workspace` 虚拟根目录；
- 拒绝路径穿越、符号链接逃逸、绝对真实路径和工作区外访问；
- 所有文件操作在解析后再次验证其规范化路径仍位于授权根目录。

## 3. 权限模型

| 权限 | 可用能力 |
| --- | --- |
| 只读 | 浏览、信息、读取、搜索、下载 |
| 读写 | 只读能力 + 创建、写入、Patch、重命名、移动、复制、上传 |
| 删除 | 独立开关；仅开启后可删除 |

Shell、Git、执行程序、访问其他本地应用不属于 v1.0 权限。权限变更必须立即使 API Scope、MCP Tools 和“复制给 AI”内容同时变化。

## 4. 身份与会话

客户端注册设备密钥；服务端签发短期会话凭证；Agent 使用 Workspace 级、可撤销、最小权限的连接令牌。令牌泄漏时，用户可在项目详情或设备管理页立即撤销；令牌过期后不可继续访问。

控制面应保存会话的用户、设备、Workspace、权限、创建/过期时间、连接方式和撤销状态。数据面必须验证会话签名与权限，不能仅信任客户端传入的 Workspace ID。

## 5. 安全写入与版本冲突

读取响应携带 `version`、`sha256` 和 `mtime`。写入、Patch、移动等破坏性操作携带 `base_version` 或等价前置条件。

```text
权限校验 → 路径校验 → 版本校验 → 写临时文件 → 内容校验 → 原子替换 → 版本递增 → 记录审计
```

若 Agent 基于版本 17 修改，而用户已将本地文件改为版本 18，服务返回 `VERSION_CONFLICT`，绝不覆盖。Agent 应重新读取、重建修改后再尝试。

## 6. 删除与审计

删除默认关闭，即使 Workspace 是读写。删除操作必须记录路径、调用方、会话、时间、结果和文件版本。后续版本可引入本地回收站，但 v1.0 至少需有完整审计记录与明确错误反馈。

## 7. 平台授权

Windows/macOS 使用原生文件夹授权与最小权限策略；Android 必须通过系统文件选择器（Storage Access Framework）持久化用户明确选定目录的权限，不能自行扫描 `/sdcard` 或申请全盘访问作为默认方案。
